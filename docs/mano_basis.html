01 · 先回答：改变的是“如何解释手形参数”

一组 MANO 参数本身并不是一只完整的手。它必须交给一个包含模板、形状基底、姿态基底与蒙皮权重的模型，才能生成三维网格。相同参数交给不同版本的模型，可能得到不同的手形。

这次比较只改变左手模型的一项：shapedirs 的 x 坐标分量。脚本保留同一帧的平移、旋转和形状参数 β，分别使用原始基底与 x 分量反号后的基底重建，所以会有“修改前 / 修改后”的几何差异。

Vstock = M(t, θ, β; Sstock)
Vflip = M(t, θ, β; Sflip)
Sflip[i, x, k] = −Sstock[i, x, k]
M 是完整的重建函数；分号右侧表示模型约定。这里参数 t、θ、β 相同，形状基底 S 不同。
必须先明确“修复”相对于谁。历史修复针对的是模型左右镜像不一致；本次调查针对的是已有数据参数与 solver 的模型约定不一致。前者可能要加一次 flip，后者可能要撤销一次 flip。视频颜色只表示两种重建方法，不直接代表正确与错误。

可以把 β 想成“配方中的十个数字”，把基底想成“这十个数字分别控制哪些变形、往什么方向变形”。数字没变，说明书变了，最后做出的手也会变。这比把 β 简单理解成“固定的掌宽、固定的指长”更准确。

02 · 用数学描述：模板 + 十种形状变形

先把手指弯曲和全局运动暂时放在一边，只看静止姿态下的形状。令顶点数 N = 778，形状维数 K = 10。

符号尺寸含义
T̄ℝN×3平均手模板；β = 0 时的形状基准。
βℝK十个形状系数，是相对于基底定义的坐标。
SℝN×3×K形状变形基底；S[i,c,k] 是第 k 个系数对顶点 i 的坐标 c 的位移贡献。
θℝ4816 个关节旋转的轴角表示，包含根旋转；不是本次更换的量。
tℝ3加到模型输出上的平移。
BS(β)i,c = Σk=1…10 Si,c,k βk
Tshape(β) = T̄ + BS(β)
逐顶点、逐坐标，把十种变形按 β 加权求和，再加回平均模板。β 常按无量纲系数处理；S、模板和输出必须遵循相同长度单位。

例如某顶点在模板中的 x 坐标是 20 mm，某一种形状模式在该点的 x 位移是 +3 mm。只启用这一模式且 β₁ = 2 时，该顶点变成 20 + 3 × 2 = 26 mm。把该模式的 x 位移反号后，则变成 20 − 3 × 2 = 14 mm。同一个 β₁ = 2，两种基底下相差 12 mm。

这只是说明计算规则的玩具例子，不能把“第一个 β”固定称为真实 MANO 的“掌宽参数”。学习得到的每种形状模式通常同时影响多个部位、多个坐标。

代码里的索引究竟代表什么？

# shapedirs 的维度：(顶点, xyz 坐标, 形状模式)
# 本仓库实际加载的尺寸：(778, 3, 10)
flip = stock.clone()
flip[:, 0, :] *= -1

[:, 0, :] 选择的是所有顶点、x 坐标、所有十种形状模式。不是只改第一个 β，也不是把 β 全部反号，更不是修改所有坐标。

03 · 历史问题：模板镜像了，变形方向却没有镜像

为讨论左右手对应关系，采用列向量坐标，定义关于 yz 平面的反射矩阵：

F = diag(−1, 1, 1),   F(x,y,z)T = (−x,y,z)T
F² = I,   FTF = I,   det(F) = −1

F 保留长度、反转左右。它是反射而不是旋转：真正的三维旋转属于 SO(3)，行列式为 +1。这里的 x 是 MANO 模型局部坐标的 x，不是屏幕水平方向，也不是世界坐标里任意定义的“左”。

在“顶点对应一致、左右模板按这个平面镜像、左右共用同一 β 语义”的理想模型中，应当满足以下两个条件：

T̄L,i = F T̄R,i
SL,i,:,k = F SR,i,:,k
⇒ TL,i(β) = F TR,i(β)

第三行直接来自线性性：F 可以分配到模板和每个形状位移上。镜像一只手时，不仅平均形状要镜像，偏离平均形状的方向也必须镜像。

历史上被报告的资产问题

SMPL-X issue #48 报告了某些 MANO 左右资产的模板不同、形状基底却相同，并展示了左手 x 分量反号的处理。把这个问题抽象化，就是：

T̄L = F T̄R,   但 SL,stock ≈ SR
TL,stock(β) ≈ F T̄R + SRβ
F TR(β) = F T̄R + F SRβ
两者只在第二项上不同：左手模板已经在镜像的一侧，形状增量却仍沿右手的方向变化。这里 Sβ 是对形状维度的张量收缩。

因此，在上述共享语义下，设置 SL,flip = F SL,stock 可以恢复形状增量的镜像关系。这个论证针对形状层；完整姿态镜像还涉及关节旋转、姿态基底和拓扑方向，不能只靠这一式声称所有姿态已严格镜像。

“左右资产存在历史镜像问题”与“某份旧标注必须改用镜像修复后的基底”是两个不同命题。第一项可以通过资产对账验证；第二项必须结合标注的生成模型和真实观测验证。

04 · 修改前后差多少？可以直接推导

以下 stock 和 flip 使用相同的左手模板。只改变 S，因此在静止形状层：

ΔTi = Tflip,i − Tstock,i
= (F − I) Σk Sstock,i,:,k βk
= ( −2 Σk Sstock,i,x,kβk, 0, 0 )T

差异是 x 方向形状增量的两倍，因为“+a”与“−a”相隔 2a。这不是把顶点本身的 x 乘 −1：模板 x 仍保持不变。

Tflip = T̄L + F(Sstockβ)
F Tstock = F T̄L + F(Sstockβ)
Tflip − F Tstock = (I − F)T̄L
两种操作一般不相同。“翻转形状基底”仍输出左手；“镜像完整左手顶点”连模板也翻转了。

β 为零时为什么看不出区别？

β = 0 ⇒ Sβ = 0 ⇒ ΔT = 0。两条重建链路的模板、姿态等都相同时，后续完整输出也相同。某些非零 β 也可能因为模式抵消，使部分顶点的 x 位移接近零。

|ΔTi,x| ≤ 2 ‖Si,x,:‖₂ ‖β‖₂
ΔTi,x = 0 ⇔ Σk Si,x,k βk = 0

所以 β 较大可以让差异更容易观察，但 max(abs(β)) 不是几何误差，也不能单独证明应该选择 stock 或 flip。

05 · 交互示意：同一个 β，两种解释

下面是一维形状模式的二维教学轮廓，不是实际 MANO 网格，也不是数据集测量。左右模板严格镜像，每个对应点的形状位移取 aᵢ = 3 mm。stock 左手沿 +x 位移，flip 左手沿 −x 位移。拖动 β 可以看到：模板虽然镜像，但 stock 的形状变化没有跟着镜像。

两者点距6.00 mm

灰虚线是 β = 0 的模板。示意采用每毫米 5 个画布单位，便于看清。这个特意简化的例子是统一偏移；实际 MANO 每个点的 aᵢ 不同，会改变轮廓、局部尺寸和关节位置。

06 · 形状变化如何进入完整 MANO 重建？

完整输出还包含骨架与姿态。为解释传播路径，使用下面的标准结构记号。它是对本地前向实现的数学概括，不把不同实现中的中心平移细节混成同一个约定。

TP(β,θ) = T̄ + BS(β) + BP(θ)
J(β) = ℛJ[T̄ + BS(β)]
Vi(β,θ) = Σj=0…15 wij [G′j(θ,J(β)) · (TP,i,1)T]xyz
Vcam,i = Vi + t
  • BP(θ)：姿态相关的表面修正，描述弯指时皮肤表面变化。
  • ℛJ：关节回归器，用顶点的线性组合确定骨架关节。
  • wij：顶点 i 受关节 j 控制的蒙皮权重。
  • G′j：根据旋转和形状相关关节位置构造、消除静止姿态偏置的变换。

这次修改没有直接改变 θ、姿态基底或蒙皮权重，但是 BS 变了，J(β) 也会随之变。因而改变 S 不只是给最终网格加一组 x 位移，还会改变骨架位置和后续运动的旋转支点。

形状基底 S→静止形状→关节位置 J→蒙皮后的网格 V→相机投影

第 04 节“只有 x 分量不同”的结论严格针对姿态变换之前的形状层。弯指、根旋转和相机旋转之后，差异可以出现在最终坐标的 x、y、z 三个分量上。正因为如此，不能从视频里差异的屏幕方向反推代码究竟翻转了哪一个坐标。

数学补充：对于固定 θ、固定蒙皮权重和线性关节回归的标准 LBS，最终顶点对 β 仍可写成仿射形式。这里强调的是输出差异需要包含骨架变化的贡献，不能直接套用静止形状层的 −2Sₓβ 当作最终三维差异。

07 · 关键：β 不能脱离生成它的模型约定

假设一个数据集使用基底 SA 对图像或三维标注进行拟合。它得到的参数可以抽象成优化问题的解：

(θ̂A, β̂A, t̂A) = argminθ,β,t L(Π(M(t,θ,β;SA)), Y) + λΩ(θ,β)
Y 是观测，Π 是投影或其他观测算子，L 衡量拟合误差，Ω 是正则化。这个表达式描述可能的参数生成机制，不声称所有数据集都使用同一个优化器。

保存参数后，如果读取端换成 SB，却继续使用同一组估计参数，重建函数就改变了：

M(t̂A, θ̂A, β̂A; SB)
≠ M(t̂A, θ̂A, β̂A; SA)  （一般情况）

拟合过程可能已经在 β、θ 或 t 中补偿了某个旧模型的行为。此时只在消费端“修好模型”，并不等于修好了整个标注。旧参数与新模型之间可能失去兼容性。

为什么不能简单把 β 乘 −1？

把 S 展平成矩阵 A ∈ ℝ3N×10。令 D = IN ⊗ F，表示对每个顶点的 x 分量反号。那么 Aflip = D Astock。若想用新基底保存原有静止形状，需要：

Aflip βnew = Astock βold
即 D Astock βnew = Astock βold

这个方程不保证对所有 βold 都有解。只有两种基底的列空间一致，才可能有全局可逆的十维换坐标规则。把 β 全部取负会同时改变 x、y、z 的形状增量；本次 flip 只改变 x，二者一般不等价。

−Aβ 通常不等于 DAβ
βnew* = Aflip†Astockβold
r = ‖Aflipβnew* − Astockβold‖₂

† 表示 Moore–Penrose 伪逆。这个最小二乘转换只针对静止形状；r 非零说明新形状子空间不能精确表达旧形状。即使 r 很小，完整姿态重建、参数先验和后续拟合仍需要验证。

可信的数据契约应记录的不只是 β: length 10，还包括资产版本或指纹、左右模型、形状基底处理、姿态均值、旋转表示、平移与中心定义、长度单位和坐标系。形状相同的数组不代表语义相同。

08 · 为什么这次“修复后”可能反而是 stock？

语境修复前修复后目的
历史模型镜像修复左手原始资产 Sstock左手 x 分量反号 Sflip在共享 β 镜像语义下，让左右形状增量一致。
某旧数据集的消费链路修复solver 强制使用 Sflip恢复参数生成时采用的 Sstock恢复保存参数与重建器之间的兼容性。
已按 flip 生成参数的数据集消费端错误使用 stock消费端采用 flip同样是恢复生成与消费的一致性。

所以“修复前 / 后”不是一种永远绑定颜色的物理属性，它是相对于某个管线缺陷的描述。long_videos.py 使用中性的 stock / flip；旁边的 ARCTIC 专项脚本则把“solver 原来统一 flip”叫 before，把“改回 stock 的候选重建”叫 after。

上一轮提到的 ARCTIC“修复后”应按这个第二层含义理解。专项脚本与 README 的命名表达的是调查中的候选修复方向，不能仅凭命名推断所有数据集都应使用 stock，或已经完成标签重算与正式安装。

正确的兼容性条件：Cconsumer = Cproducer
或存在经过验证的转换 τ，使
Mconsumer(τ(p)) ≈ Mproducer(p)
C 是完整模型约定；p 是保存参数。对于决定更新目标几何而非保留原几何的修复，应重新拟合或重新确认目标，并重新验证下游标签。

更清晰的描述是“从 always-flip 改为匹配数据集生成约定”，或“在该资产上启用镜像形状修复”。这能明确动作与目标，避免只写含糊的“左手已修复”。

09 · long_videos.py 生成了什么证据？

脚本从 HMR parquet 获取保存的手部参数，布局如下：

raw61[0:3]   = t       # 平移
raw61[3:51]  = θ       # 16 × 3 轴角
raw61[51:61] = β       # 10 个形状系数

v_stock = ManoLeft(θ, β; stock) + t
v_flip  = ManoLeft(θ, β; flip)  + t
v_right = ManoRight(θ_right, β_right) + t_right

相机到世界的刚体变换记作 Rcw、tcw。脚本先把手从相机系转到世界系，再用同一帧的逆变换投回相机：

vw = Rcwvc + tcw
v′c = RcwT(vw − tcw) = vc
u = fxX/Z + cx,   v = fyY/Z + cy

两次坐标变换在数学上抵消（数值误差除外），所以这里的红绿差异来自形状重建，不来自两条不同的相机链路。它没有物体网格、力向量或 solver 输出，也不读取 tactile 接触结果来生成手。

画面元素准确含义不能直接说明什么
红色同一左手参数，使用 x-flip 基底。不能仅凭红色称它为“错误”。
绿色同一左手参数，使用 stock 基底。不能仅凭绿色称它为“修复后正确”。
蓝色右手重建参照，未参加左手基底切换。不是已验证的绝对真值；没有右手标注时不绘制。
Lbeta当前帧 max(abs(βL))。不是毫米误差、置信度或修复评分。
LP / RP左右手 present 标记。present 不等于手一定完整可见或标注一定准确。

为什么需要连续视频？

连续片段可以判断某种偏差是否持续存在，以及轮廓偏差是否随姿态变化。单帧可能因遮挡、透视或手指重合，让某种基底偶然显得更好。若手形、时序与相机都可信，跨姿态和跨视角的持续贴合才更有说服力。

原入口固定种子 20260927，计划每个数据集抽 10 个 observation，目标 20 秒。抽样有放回；可用 ego 与 exo 时交替选择；窗口优先左手出现率 ≥ 30%，找不到时可接受包含少量左手的窗口。短于 5 秒的窗口原入口跳过。

当前目录共有 12 × 10 = 120 个 MP4，但也包含补样脚本和 DexYCB 专用入口的结果。DexYCB 的 10 个片段约 2.4 秒，只覆盖 2 个 episode 的多个视角；HOCAP 补样最长约 59.3 秒。因此不能把整个目录当作统一的“120 个独立随机 20 秒样本”。

审阅时的限制

  • 对齐：视频读取采用 episode 起始帧 + HMR 行偏移，没有通用的 source-position 映射验证。这里读取的是 HMR 行，不是 solver 行；不能直接把 solver 的 ARCTIC +12 映射套到 HMR，但同样需要确认 HMR 与视频逐帧对应。
  • 相机：使用 cameras 表里的固定针孔内参，不处理畸变或逐帧内参。未校准的共同偏差会影响两种候选的绝对贴合。
  • 遮挡：用三角形区域做半透明覆盖，没有物体或手之间的深度遮挡。被物体挡住的手部仍可能显示。
  • 混色：先画蓝，再画红，再画绿。若红绿区域重合，后画的绿色会更显眼，不表示绿色“赢了”。
  • 判定：samples.json 保存抽样与生成信息，不包含自动 stock/flip 判决。原入口的 secs 是生成耗时，补样入口的 secs 采用另一种含义；片段时长应由帧数 / fps 或视频元数据计算。
红绿都不贴合 → 先查时间、相机、参数与模型其他约定；红绿几乎重合 → 该样本对基底选择的信息不足；某色持续更贴合 → 是支持该候选的视觉证据，还应结合官方生成代码和三维对账。

10 · 为什么这会影响接触与力，而不只是显示？

接触算法使用的是三维表面。设物体表面为 O，手顶点为 vᵢ。最简单的几何接触候选可按距离阈值定义：

di = dist(vi, O) = infq∈O ‖vi − q‖₂
ci = 𝟙[di ≤ ε]

这个式子用于解释阈值敏感性，不声称 solver 只使用这种简单规则。即使模型只偏移数毫米，也可能让某顶点越过接触阈值。对于同一物体表面的无符号距离，距离函数有 1-Lipschitz 性：

|dist(vi + Δvi, O) − dist(vi, O)| ≤ ‖Δvi‖₂
若 |di − ε| > ‖Δvi‖₂，则该简单阈值分类不会因这次位移翻转。

反过来，距离阈值越近的点越敏感；上界不等于实际距离变化，也不意味着所有接触一定改变。对于依赖法向、穿透、时间一致性等规则的算法，需要检查这些额外量。

接触点位置改变还会影响力矩。若参考点 o 不变、暂时保持每个接触力 fᵢ 不变：

τ = Σi (vi − o) × fi
Δτ = Σi Δvi × fi
‖Δτ‖₂ ≤ Σi ‖Δvi‖₂ ‖fi‖₂

位移还可能改变表面法向、接触集合和优化约束，从而让 fᵢ 本身也变。最近接触点跨过边缘时，法向甚至可能突然变化。因此“把展示的手网格换正确”不代表已经修复求解时生成的标签。

若确认正式标签曾使用不匹配的几何，应追踪实际求解版本和受影响范围，再重算或验证相关接触与力输出。这个 HTML 和长视频只是解释与审阅证据，不代表已经执行了几何修复、标签重算或重新发布。

11.5 怎样才能判断一个数据集应该用哪种？

12 · 常见疑问、来源与边界

为什么主要讨论左手？右手不需要修吗？

这里讨论的历史资产问题是相对于右手约定的左手镜像形状增量不一致，常见处理因此作用于左手。右手在这次 A/B 中没有修改，不代表所有右手参数、相机和时序天然正确。

翻转一次，再翻转一次，会怎样？

F² = I，所以对同一个基底执行两次相同 x 翻转，会回到原始基底。单次反号操作不是幂等的；不能不检查当前资产状态就把它当成“重复执行也安全”的修复。

能不能用左右手大小是否一致来自动判定？

可以作为筛查线索，但不应作为最终真值。左右参数可能独立拟合、真实手形可能有差异、标注质量和视角也可能不同。最重要的是生成约定与可信几何 / 观测的对账。

红绿重合，是不是证明不需要修复？

只能说明这段参数或这个视角下不敏感。β 接近零、形状模式抵消、投影把深度差隐藏、遮挡或视频分辨率低，都可能让差异难以看出。

相机旋转能把形状基底错误补回来吗？

一般不能。相机刚体变换对全部点采用同一个旋转和平移，而基底更改产生的位移随顶点而异，通常改变局部尺寸。改变相机可能补偿某些观测误差，却不是通用的形状修复。

这与 axis-angle、flat_hand_mean 或 manotorch 的解剖旋转基底相同吗？

不同。这里 S 是 β 的形状变形基底；轴角和姿态均值决定 θ 如何解释；manotorch 的解剖旋转坐标基底用于分析关节运动。它们都属于模型约定，但本次脚本直接切换的只有 th_shapedirs。

外部一手来源

  • MANO 官方项目页：原模型与论文入口。本页的镜像差值、兼容性条件和误差传播表达为解释性推导，不是逐字转载论文。

  • manotorch 前向源码：可核对形状混合、关节回归与蒙皮实现；实际工作区使用的是本地版本，已另外核实相关路径。

14 · 如果最终要统一到一个基底，应该怎样迁移？

建议目标：固定资产版本的 corrected 左手基底（本地 stock 的 x 分量翻转），右手保留原基底。这样建立一致的左右形状镜像语义，也与 HOT3D、Show3D、ReInterHand 当前采用的约定相符。这里定义的是最终模型，旧数据不能不经迁移就直接用新模型解释。

不仅统一 shapedirs，还要固定前向库版本、full axis-angle、flat_hand_mean=True、center_idx=None、米单位、778 顶点对应关系、平移定义和坐标系；通过资产内容指纹避免重复翻转。MANO 官网说明 v1.2 没有修改模型文件，版本名称本身不能证明资产已修复。

按原约定解码→可信参考顶点轨迹→canonical 模型重新拟合→消费者验证与标签对齐

stock 组的参考几何是 stock 解码得到的原数据手形。迁移的目标是让 corrected 模型继续表达这只手，而不是保留旧 beta 后把手形改成视频中较差的红色。flip 组在完整约定一致时通常可以直接保留参数，仍需检查姿态均值、资产和中心定义。
